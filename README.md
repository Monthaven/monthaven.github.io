# monthavencapital.com — Monthaven Home Buyers

Cash home-buyer lead generation site for **Gaston, Cleveland & Lincoln County, North
Carolina**. Static HTML generated by [Eleventy](https://www.11ty.dev/), deployed to GitHub
Pages.

---

## Adding content without touching a template

This is the whole point of the build. Every city page, situation page, and FAQ is generated
from a data file.

| To add… | Edit this | Result |
|---|---|---|
| A city | `src/_data/cities.json` — add one object | A full page at `/sell-my-house-fast-<slug>-nc/`, plus footer, service-area, and nearby-city links everywhere |
| A situation | `src/_data/situations.json` | A page at `/<urlPrefix>-nc/` and a card in every situation grid |
| A blog post | Drop a `.md` file in `src/blog/` | A post at `/blog/<filename>/`, listed on `/blog/` |
| A general FAQ | `src/_data/faqs.json` | Appears on the FAQ page and in `FAQPage` schema |
| Proof (deals, reviews, bios) | `src/_data/proof.json` | Renders sitewide — see **Launch blockers** |
| Phone, email, offer terms | `src/_data/site.json` | Changes everywhere at once |

Commit and push to `main`; GitHub Actions builds and deploys. You never run `npm`.

### Where the lead goes

Two endpoints in `src/_data/site.json`, and both matter.

`leadEndpoint` is Monthaven's own intake: `POST /api/sms/web-lead` on SONA. A submission
there records the TCPA consent evidence, creates the lead and its ledger row, texts the
seller a confirmation, and alerts Alec on push and SMS. The lead lands as `INTERESTED` with
`call` as its next action, assigned to Alec.

`leadEndpointFallback` is Formspree, and it is not decoration. SONA runs on a local Windows
box behind a Cloudflare tunnel. When that box is down the primary POST fails and
`src/js/main.js` re-posts the same submission to Formspree, so a dead tunnel costs us a
confirmation text, never the lead. Failover happens on transport and 5xx errors only: a 4xx
means the primary read the submission and rejected it (bot trap, bad input, rate limit), and
re-posting that would just duplicate a bad lead.

Two things about the primary that are easy to break:

- **It takes JSON, not multipart.** SONA parses JSON and urlencoded bodies only. Handing a
  bare `FormData` to `fetch` sends `multipart/form-data`, which arrives as an empty body with
  no error on either side. `main.js` serializes to JSON for the primary and keeps `FormData`
  for the Formspree fallback, which does want multipart.
- **The origin is allowlisted server-side.** `https://monthavencapital.com` and the `www.`
  form are listed in SONA's CORS config. A new domain or subdomain fronting this site will
  fail its preflight until it is added there too.

Swapping either endpoint is still a one-line change. There is no second copy anywhere.

```bash
npm run build && npm run check   # confirm before pushing
```

## Launch blockers

`npm run check:launch` fails until these are filled with **real, verifiable** material.
Nothing is ever fabricated to satisfy them — an invented testimonial or deal count is both
a legal exposure and the fastest way to lose the trust these pages exist to build.

1. **Real closed deals** — `proof.caseStudies` (address, condition, days to close, outcome)
2. **Real testimonials** — `proof.testimonials` (first name + city, with permission)
3. **Real team bio and photo** — `proof.team`. Biggest E-E-A-T signal on the site.
4. **Verified value-stack figures** — `proof.valueStack.rows`
5. **A guarantee you will actually honor** — `proof.guarantee`, then set `enabled: true`
6. **Google Business Profile URL** — `site.social.gbp`, and confirm the site's phone and
   business name match the GBP **character for character**

Until then the site builds and is fully reviewable; the proof blocks render a visible
"awaiting real material" note rather than anything invented.

## ⚠️ Four URLs that must never move

```
/text/      /privacy/      /terms/      /legal/sms/
```

`https://monthavencapital.com/text` is filed with the mobile carriers as the
**proof-of-consent URL** for the toll-free A2P messaging campaign, and carriers re-check
it. If it 404s or redirects elsewhere, the number can be flagged or shut off. The
`opt_in_url` hidden field on that page must keep its exact filed value.

`scripts/check-links.mjs` fails the build if any of the four is missing or if that hidden
field changes. Do not weaken that check.

**Also outstanding:** the A2P registration (`docs/toll-free-verification-answers.md`)
describes the *old* business — investor scheduling, "no promotional messages." Texting
homeowners about a cash offer is a different, consumer-facing use case and the
registration needs to be re-filed to match before SMS marketing begins.

## Local development

```bash
npm install
npm run serve     # http://localhost:8080, live reload
npm run build     # → _site/
npm run check     # links, assets, canonicals, frozen URLs, content depth
npm run check:launch   # the above + launch blockers
```

## Build gates

`npm run check` runs in CI and blocks the deploy. It fails on:

- a dead internal link or a missing referenced asset
- a canonical that disagrees with the page's own URL or its sitemap entry
- a `.html` URL or a redirect stub or a `noindex` page in the sitemap
- internal markdown published to a public URL
- any of the four frozen URLs missing, or a changed `opt_in_url`
- a request to Google Fonts or a hotlinked Unsplash image
- a city/situation/post page under its word-count floor
- two city or situation pages more than 72% identical (Jaccard, over trigrams)

Every failure the previous version of this site shipped with would have been caught here.

## Structure

```
src/_data/       cities · situations · faqs · proof · site · redirects   ← content lives here
src/_includes/   layouts · partials (head, header, footer, schema) · components (lead-form, blocks)
src/generate/    city.njk · situation.njk · redirect-stub.njk   ← paginated over the data files
src/pages/       hand-written pages
src/blog/        markdown posts
src/css/         00-tokens · 01-reset · 02-base · 03-layout · 10-components · 30-utilities
scripts/         check-links.mjs · check-content.mjs
docs/            internal notes and compliance guides — outside src/, never published
docs/archive/    the previous capital-advisory site
```

## Technical notes

- **Zero third-party requests** except Google Analytics. System font stack, no webfont.
  The full stylesheet is inlined in `<head>` (budget: 20KB raw, enforced in
  `src/_data/css.js`), so there is no render-blocking request and no FOUC.
- **No image above the fold** — LCP is a text node.
- **Canonicals are computed** from `page.url` in one partial and never hand-typed.
- **Schema** (`LocalBusiness` + `areaServed`, `FAQPage`, `BreadcrumbList`, `BlogPosting`)
  is generated from the same data that renders the page, so structured data and visible
  content cannot drift. **No `PostalAddress`** — Monthaven is a service-area business, and
  publishing an out-of-market address is a real ranking and trust risk.
- **Redirect stubs** use meta-refresh + canonical + `noarchive`. Not `noindex`, which would
  conflict with the canonical and block signal consolidation.
- **Partial lead capture** (posting step 1 before step 2 completes) is built but **off** by
  default — `site.partialCapture`. It doubles submissions against the form provider's quota.
  Turn it on when the endpoint is Monthaven's own.
